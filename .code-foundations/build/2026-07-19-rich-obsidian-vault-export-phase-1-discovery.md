## Design Decisions

### Design: episodic export scan + stage (aposd-designing-deep-modules)

#### Approaches Considered
1. **A — Byte budget hidden inside `store.ScanEpisodic`** (seam exactly as the plan pins it: `ScanEpisodic(ctx, tenantID, after string) ([]memory.Episodic, string, error)`); the scan fetches a count-bounded page, truncates at the byte budget, and derives `nextAfter` from the **last included** record's sort key.
2. **B — Budget in the server handler**: store returns count-bounded pages; the handler trims to the byte budget. Broken by construction: the seam's single `nextAfter` points past the trimmed records, so trimmed records are lost — fixing it requires per-record resumability leaking into the seam.
3. **C — Widen the seam with size/budget parameters**: caller controls paging policy. Leaks paging internals to the consumer, contradicts the plan's pinned `Produces:` signature, and no second caller needs it.

#### Comparison
| Criterion | A | B | C |
|-----------|---|---|---|
| Interface simplicity | 1 method, 3 args | 1 method but handler grows trim logic | 1 method, 5 args |
| Information hiding | budget + sort key + token format all internal | cursor semantics leak across the seam | budget policy leaks to caller |
| Caller ease of use | round-trip an opaque string | caller must reconcile trim vs cursor (correctness bug) | caller must choose budgets |
| Cursor correctness | exact (cut point = last included) | wrong (skips trimmed records) | exact but caller-burdened |

#### Choice: A
Rationale: only A keeps the cursor correct while matching the plan's pinned seam. The budget, sort key, `search_after` mechanics, and token format are all implementation details the store hides; the server round-trips an opaque string. Sacrifice: the server can't tune the budget per call — irrelevant, there's one caller.

#### Depth Check
- Interface methods: 1 (`ScanEpisodic`)
- Hidden details: OpenSearch query shape, `(created_at, event_id)` sort key, `search_after` token encoding, byte budget, count cap, index-missing tolerance, processed/dead-letter filtering
- Common case complexity: simple (empty string in, records + string out, "" = exhausted)

### Point decisions
- **Seam record type = `memory.Episodic`** ("graph-free episodic record" per the plan): transport-free, already crossed by the `EpisodicReader` seam, carries the ACL fields `canExport` authorizes against before projection (fetch → authorize → project, the Read RPC's established ordering).
- **Sub-cursor token**: JSON `{"c":<created_at unix-millis>,"e":<event_id>}` produced/parsed only by the store. Delimiter-safe for arbitrary client-supplied event_ids (a `|`-delimited format would be forgeable/ambiguous). An undecodable token returns a wrapped **`store.ErrBadCursor`** sentinel; the server translates it to the same opaque `InvalidArgument "invalid cursor"` as `decodeExportCursor` — a forged sub-cursor can only reject or reposition inside the caller's own tenant (tenant term is pinned server-side, never cursor-carried).
- **Byte budget** `EpisodicPageByteBudget = 2 MiB` (exported const, mirroring `DefaultScanBatchSize`): counts `Text` bytes (the unbounded field; the fixed-size fields ride in the 2 MiB headroom under the 4 MB gRPC cap). Progress guarantee: a page always carries ≥1 record even if that record alone exceeds the budget — otherwise an oversized record would wedge the export forever (documented degenerate case, tested).
- **Wire cursor**: `stageEpisodic` prepended to the state machine; `exportCursor` gains `EpAfter string \`json:"e,omitempty"\`` (the episodic string sub-cursor; `After graph.Cursor` stays for entity/edge stages untouched). Empty wire token now decodes to `{Stage: stageEpisodic}`. Old in-flight entity/edge cursors remain valid (stage set preserved).
- **nil `EpisodicExporter` = empty episodic tier** (chain straight into entities), NOT `Unimplemented`. Rationale: (a) the existing anchored export tests construct `Server{Exporter: b}` and must stay green (test anchoring); (b) it mirrors the "nil seam disables the feature" convention (nil ACL, nil Auditor) without disabling the graph export that IS wired; (c) not a silent failure in APOSD's sense — production `main.go` wires it unconditionally, and the seam doc states the contract. `Exporter == nil` still gates the whole RPC as `Unimplemented` (unchanged).
- **Filtering (processed + non-dead-lettered) lives in the scan query**, not re-checked in the handler: it is an extraction-status filter, not a tenant/ACL boundary — the security-critical check (`canExport` per record, ACL error fails closed) IS re-run in the handler per cc-defensive-programming's defense-in-depth rule.
- **Proto**: `ExportEpisodic{event_id=1, kind=2, text=3, occurred_at=4, source_ids=5, scope=6, team_id=7, owner_agent_id=8}` (plan's pinned field set; no `text_embedding`, no outbox fields — internal); `ExportResponse.episodics = 4`.
- **Client view**: `engramclient.ExportEpisodic{EventID, Kind, Text string; OccurredAt *time.Time; SourceIDs []string}` — exactly the plan's `Produces:` (ACL fields stay server-side wire metadata; the client renderer doesn't need them).
