§ 02 — Foundations

Why memory, not just more context

A bigger context window is not a memory system. Three findings define the problem Engram is built to solve.

(a)

Long context ≠ memory

On the BEAM benchmark, structured memory beats a 1M-token context window by ~75% at 1M tokens. Reading more is not the same as remembering better — past a point, raw context dilutes rather than informs.

(b)

Experience-following is a risk, not a feature

Agents obey retrieved experience — input↔output correlation runs at r ≈ 1 — so a single wrong memory actively steers behavior wrong. Curated-small beats large-noisy: accuracy rose 38.7% → 42.1% while the store shrank.

(c)

Multi-agent needs shared memory

Several agents working the same problem need one shared memory — with scoping, access control, and concurrent-write safety. That is a systems problem, not a prompt.

§ 04 — The write path

Sync append, async extract

Ingest must be cheap and never block. Extraction — the expensive, LLM-driven part — happens off the hot path, where it can take its time and be reconciled carefully.

§ 05 — Retrieval

Hybrid, not RAG-vs-FTS

The argument between keyword search and vector search is a false choice. Engram runs both and fuses them.

BM25 catches exact terms — IDs, names, error codes — the things a paraphrase loses. kNN catches semantic and paraphrased matches that share no literal tokens. Reciprocal Rank Fusion merges the two rankings without tuning a blend weight. OpenSearch does all three natively in one query.

Every result is filtered before it reaches the agent — invalid_at = null, expired_at = null, plus scope / ACL. Retrieval never returns a fact that is superseded, expired, or out of the reader’s reach.

§ 06 — Bi-temporal truth

Four timestamps, never a delete

A fact has two independent timelines: when it was true in the world, and when we knew it. Conflating them loses history.

①

valid_at / invalid_at

When the fact was true in the world. A new contradicting fact sets the old one’s invalid_at to the new fact’s valid_at — closing its window without erasing it.

②

created_at / expired_at

When the system knew the fact. Nothing is ever deleted — so you get a full audit trail and point-in-time queries: “what did we believe on date X?”

§ 07 — Multi-agent

Provenance is the ACL

In shared memory, “who may read this?” should not be a separate permission table that drifts out of sync. The answer is already in the data.

Every memory fragment carries its provenance — the owning user, the agents that contributed to it, the source resources it was built from. A reader sees a fragment only if it can reach all of those contributors and resources (subset semantics). Because the check runs at query time, revoking access to a resource takes effect on the very next read — revocation is instant.

Concurrent writes to the same fragment use OpenSearch optimistic concurrency plus a version chain — the part no published memory system solves, and where Engram makes an original contribution.

§ 10 — The honest part

The hardest problems

The parts that are genuinely unsolved — named plainly, because pretending otherwise is how memory systems quietly fail.

⚠ Hard problem 01

Concurrent-write merge in shared memory

When multiple agents write the same fragment at once, no published system has a clean merge. This is our own design space — optimistic concurrency plus a version chain — and it is where the most original work sits.

⚠ Hard problem 02

Experience poisoning

One bad lesson propagates through experience-following and gets obeyed. Defense is layered: a write-gate at intake, utility-based pruning over time, and a quarantine tier the literature has not yet built.

⚠ Hard problem 03

Extraction cost at billions scale

LLM extraction is the dominant cost line. Containment is a selective “worth remembering” gate, cheaper models for the common case, and aggressive batching — so we only pay to remember what matters.
