Engram.

Memory an agent can trust.

Engram is a single gRPC service backed by OpenSearch. It combines hybrid retrieval, four persisted memory tiers, asynchronous LLM-gated writes, document collections, and provenance-as-ACL access control behind one authenticated contract.

Go 1.25 · OpenSearch 3.1 (pinned) · Faiss HNSW kNN + BM25 + RRF · BGE-M3 1024 dimensions · gRPC / protobuf

01 · Platform overview

One daemon, explicit seams

Clients see one authenticated service. Inside it, write, read, extraction, embedding, access control, and collection registry concerns meet at narrow Go interfaces; OpenSearch owns durable state and ranked retrieval.

03 · Service assembly

Boot is a contract check

cmd/engram-server/main.go applies every embedded index template and the engram-rrf pipeline, creates indices idempotently, and refuses any OpenSearch version outside 3.1.x. It then validates configured names against template prefixes.

  1. Embedder: -embed-url selects the TEI-style HTTP adapter; empty selects the deterministic fake. Startup fails unless its dimension is exactly 1024.
  2. ACL: the ACL edge store feeds both the read filter and the store’s write guard.
  3. Data seams: OpenSearchStore serves writes; OpenSearchRetriever carries the ACL filter and tier-to-index map for reads.
  4. Background work: enrichment, worker pool, sweeper, cost logger, experience pruning, and telemetry start with the daemon.
  5. Extractor: -extract-url selects the HTTP extractor; empty uses deterministic rules. A gated wrapper fails closed if the extraction budget is breached.

Interceptor chain, outermost first

telemetrygrpc.UnaryServerInterceptor → RED metrics before auth
authgrpc.UnaryServerInterceptor → verify bearer token, inject Identity, otherwise opaque Unauthenticated
server handlers → assume a verified Identity is present

A single server.Server implements memory and knowledge RPCs from the Probe, Auditor, ACL, Registry, KnowledgeWriter, KnowledgeReader, Episodic, and Exporter seams.

05 · Write path

Append now, extract safely

Ingest synchronously appends an episodic event. That same record is the durable enqueue for asynchronous extraction, reconciliation, and post-write graph or experience work.

  • Idempotency: one SHA-256 ledger row for {tenant_id, event_id, extractor_version}. Replays short-circuit; an Extracted entry resumes from cached extraction without calling the LLM.
  • Concurrency: guarded updates with sequence number and primary term let only one worker win a lease.
  • Bi-temporal writes: update and invalidate create the successor first, then guarded-close the predecessor. Late arrivals land as bounded history. Memory records are never hard-deleted.
  • Repair: the sweeper converges partial writes, divergent siblings, expired incomplete ledgers, and closed-closed overlaps to a documented five-minute-or-less SLO.
06 · Read path

Filter before fusion

Search fuses BM25 and kNN within each tier, merges the tier lists, and applies authorization plus projection before a hit crosses the wire.

Tenant, ACL, optional owner, and semantic current-state filters sit inside both BM25 and kNN clauses, preserving filtered-kNN recall. RRF runs per tier with rank_constant=60; cross-tier results use a stable score sort, with no score normalization.

Read-side embedding has a 50 ms bound. A timeout or error falls back to BM25. Read and Audit apply the same fail-closed policy: unknown IDs, cross-tenant rows, and source mismatches return NOT_FOUND, avoiding an existence oracle.

07 · Access control

Provenance is the ACL

Memory authorization is calculated from who wrote a record and the scope they chose. Checks run at query time and write time, and every error path fails closed.

ScopeRead conditionWrite condition
private (also empty)Own owner_agent_id.Any valid identity.
teamOwner is reachable and team_id is in reachable teams.Writer belongs to the target team.
orgOwner is reachable.Writer holds the organization grant.

Reachability is resolved from engram-acl-edges on every call, with no cache, so revocation takes effect on the next request. Self is always reachable. An empty reachable-agent set denies all.

The OpenSearch clause and its in-Go twin both enforce the policy. Knowledge collections do not use provenance ACLs; internal/knowledgeauth checks public access or verified token roles through AuthorizeRead and AuthorizeWrite.

08 · Knowledge platform versus memory

Same cluster, different rules

The knowledge platform never writes a memory tier. Its runtime-mutable collections are a deliberate exception to memory’s append-only model.

ConcernMemory tiersKnowledge platform
Write modelAppend-only; never overwrite.Upsert by ID through bulk index.
DeleteBi-temporal close; never hard-delete.Mark-and-sweep hard delete.
RetrievalBM25 + kNN + RRF, then tier merge.BM25 with declared filters and sort.
ExtractionAsync extraction to facts.None; stores documents as supplied.
AccessScope and provenance ACL.Per-collection role-based policy.

The durable registry lives in knowledge-collections-000001, with a whole-set in-process cache invalidated on write. Changing a field type reindexes to vN+1 and atomically swaps the collection alias. The harvester feeds only Knowledge* RPCs.

09 · Embedding

Co-located by contract, selected by configuration

embed.HTTPEmbedder posts {baseURL}/embed with {"inputs":[...]} and expects index-aligned vectors. Without -embed-url, the daemon uses a deterministic fake.

  • Default production model: BAAI/bge-m3, 1024 dimensions. A mismatch fails boot.
  • engram-embed-server is the deterministic TEI-compatible stand-in used by local end-to-end runs.
  • Fact embedding on write is best-effort. BM25 still serves an unembedded fact, and enrichment backfills it later.
  • Query embedding is capped at 50 ms and degrades to BM25-only on failure.
10 · Deployment topology

Local compose, AWS converge

Local: compose runs OpenSearch 3.1.0, the deterministic embed server, the chat-completions stub, and the daemon service. The host extraction shim is intentionally outside compose.

Data-loss warningmake e2e and make e2e-down run docker compose down -v, wiping the OpenSearch volume used as the live local memory store.

AWS: engram-deploy performs an idempotent Go converge, without Terraform, for an OpenSearch Service 3.1 domain, three ECS services, Secrets Manager, and a VPC per staging or prod environment. It supports -rollback.

The daemon exposes Prometheus metrics at :9464/metrics. It has no HTTP health route; liveness is the authenticated gRPC Status RPC.

Harvester and source types

engram-harvester is a one-shot, manifest-driven process for cron or systemd. It calls KnowledgeCollections to validate, KnowledgeIngest per batch, then KnowledgeDelete for the sweep. Its token comes only from ENGRAM_HARVESTER_TOKEN.

Flags: --manifest*; repeatable or CSV --collection and --source; --addr (:7070); --batch-size (500); --timeout (6h). --once and --backfill are no-ops because every run is one-shot.

Source typeRequired and optional keys
arxiv-kagglepath*; filter, dump_date
arxiv-oaipmhbase_url, set, metadata_prefix, lookback
github-reposrepos*; files, base_url, max_file_bytes
web-crawlseeds*; max_pages (100), max_page_bytes, delay, max_frontier, user_agent

The crawler blocks loopback, RFC1918, link-local, IPv6 ULA/link-local, multicast, and unspecified addresses on every dial. It caps redirects at ten, rechecks cross-host redirects, honors robots.txt, and applies a per-host delay.

Authentication and tokens

Tokens are opaque 256-bit values with the egm_ prefix and base64url body. Only their SHA-256 hash is stored; the raw token appears once at issuance. Verification does a hash lookup, constant-time comparison, then revocation and TTL checks.

The resolved identity is {TenantID, UserID, AgentID, Roles[]}. harvester or admin permits knowledge ingest/delete; admin permits collection create/update. Roles come only from the token record. Memory access uses scope/provenance instead.

12 · Known document / code drift

Trust the running contract

The source architecture document calls out three stale descriptions elsewhere in the repository.

cmd/engramd

The README and several comments name it, but the directory is empty and has no main.go. The production daemon is cmd/engram-server.

docs/mcp.md

It documents three MCP tools. The code and API reference expose ten: four memory tools and six knowledge tools.

Co-located embeddings

The contract supports a co-located embedding service, but the daemon runs the deterministic fake unless -embed-url is supplied.
